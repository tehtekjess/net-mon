# Architecture and operational decisions

The preview selects WFP Security audit subscriptions as its production candidate. No custom driver or private IOCTL is used. P0 acceptance remains provisional until the full live coverage/performance matrix has been measured.

The service runs as LocalSystem because it reads the protected Security channel and queries audit policy. Its pipe ACL admits SYSTEM, elevated administrators, and the installer-selected owner SID. Requests are framed, limited to 2 MiB, parsed with bounded nesting, authenticated through pipe impersonation, and restricted to a fixed command set. Remote pipe clients are rejected. The production UI verifies the pipe server PID against the running service and verifies its protected image configuration through Service Control Manager before exchanging application data. Demo mode verifies the executable path directly. ProgramData access is restricted to SYSTEM and administrators; the UI obtains data only through IPC.

The pull-model collector follows the [Windows Event Log subscription model](https://learn.microsoft.com/en-us/windows/win32/wes/subscribing-to-events). It supplies a bookmark only when resuming, starts its signal ready to drain replay, and checks the existing subscription at most once per second as a fallback. An empty Windows 10 ERROR_INVALID_OPERATION result is treated like no more items only when no handles were returned, consistent with the handling in [pywin32's event API implementation](https://github.com/mhammond/pywin32/blob/main/win32/src/win32evtlog.i).

The collector copies bounded rendered event fields into a 32 MiB queue. Rendering and bookmark generation do not perform executable hashing or disk writes. An enrichment worker resolves process metadata and hands bounded batches to a storage worker. The shared capture/enrichment budget remains 32 MiB. The storage worker exclusively owns SQLite, configuration changes, classification, checkpoints and notification state. It alternates queued commands and capture batches when both are ready. Retained events commit before recent records/notifications and a checkpoint are published. Settings saves use flush plus atomic replacement. No user-provided path is accepted by service commands.

The UI has independent change-notification, view-preparation, ordered-action, diagnostic and tray-shell workers. A one-second bounded long-poll waits for service revisions; a five-second health heartbeat checks collector status. Status and alert processing coalesce to at most four updates per second, and visible view refreshes to ten per second. Explicit view/search changes bypass the refresh delay. Hidden/minimized windows stop table queries while alerts remain active. The tray worker coalesces pending tooltip and alert summaries; unchanged tooltips do not call Explorer, and no producer mutex is held during Shell_NotifyIcon. Explorer recreation requests are also asynchronous. Sidebar buttons avoid the main view combo box's synchronous dropdown-opening delay. Generation checks discard superseded view results. A cancellation event aborts obsolete client I/O. Four pre-created authenticated pipe instances prevent a slow session from holding up every request; per-session framing/timeouts and authorization are unchanged.

The map view uses the same bounded recent query as Recent activity. The view worker loads the offline country ranges and simplified Natural Earth geometry once, groups distinct public destination IPs by country, aggregates process paths/ports/classification and prepares all display strings. Explicit local and reserved address categories never acquire a plotted location. Country points are representative labels from Natural Earth, not IP coordinates. Grouping is bounded by the 200-record query; geometry is immutable and shared across snapshots. The map loader caps file size, country count and vertices and validates finite coordinate ranges.

Native GDI+ renders a cached basemap. Resizing, zoom/pan, geometry or appearance changes invalidate that cache; ordinary connection refreshes repaint markers over the existing bitmap. Native country/IP controls preserve selection and avoid unchanged resets. While the country dropdown is open, a single latest snapshot is deferred until close, preventing live refreshes from disrupting the chooser. Hidden map controls are not repopulated.

The theme owns its GDI resources and uses documented Windows APIs, without a browser runtime or private dark-mode ordinals. Custom-painted native buttons, list rows, headers and combo surfaces retain their native control semantics. Fonts/layout scale with window DPI. Dark title-bar requests are best-effort; Windows-owned scrollbars/dialogs can retain system colors. Theme preferences load on the event worker and save atomically through the action worker. The UI changes palette immediately. High-contrast/system-theme handling is present but still needs the release accessibility matrix.

The view worker parses responses, performs offline country lookups and formats virtual list rows/detail text into an immutable shared snapshot. Import parsing and export serialization/disk writes use the ordered action worker. At most 32 outstanding actions, including undelivered acknowledgements, are admitted. Mutations are never automatically retried: an interrupted response may require checking saved state before retrying. The UI supplies cached cell text to the native list-view and only updates details on a selection change. Refreshes preserve selection by event ID and retain the visible top-row anchor; unchanged results and responses to superseded view/search requests are discarded. When the row order is unchanged, only changed visible rows are invalidated and selection is not reset. Structural updates change the native count only when it differs and adjust only the affected selection. They do not toggle WM_SETREDRAW, which can change visibility and provoke unnecessary accessibility tree changes. Repeated feedback text is also suppressed. A coalescing mailbox keeps the latest view/status/config/alert and all bounded action acknowledgements, with one pending UI wake. Its consumer uses try-lock and reschedules instead of waiting on a producer.

Local review filtering uses explicit address categories plus a cached snapshot of operational adapters' IPv4 prefixes. Adapter enumeration runs on the storage worker every 30 seconds, and is never performed by a row-selection callback.

All Win32 control updates occur on the UI thread through posted messages. IPC operations time out, and shutdown cancellation drains pending I/O before destroying OVERLAPPED structures. No connection waits for this app's decisions.

The service atomically publishes immutable recent/status/config snapshots. Their readers never acquire the storage queue lock or perform disk I/O. Publication uses a short revision/condition-variable critical section; it does not assume that C++ atomic shared pointers are lock-free. History reads and mutations enter a bounded 64-entry command queue. History clients that disconnect set a shared cancellation flag; SQLite's [progress callback](https://www.sqlite.org/c3ref/progress_handler.html) interrupts a long scan. The connected-session callback uses [PeekNamedPipe](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe) on an overlapped pipe; the storage worker receives only the cancellation flag, never a reusable pipe handle. Accepted mutations finish even after a disconnect.

The SQLite store has one owner. Closed 8 MiB segments are immutable; new transactions use an active segment. Batches hold at most 32 records per transaction. Quota maintenance leaves two segment sizes plus headers as reserve for active growth and rollback, and only removes exact, regular-file history segment names in its controlled directory. SQLite's max_page_count bounds each active segment. A storage failure surfaces an error and increments lost-processing counts.

The production message pump measures queued input age and dispatch duration. A separate watchdog posts at most one outstanding heartbeat and captures a bounded wait-chain sample during stalls. A 32-entry slow-handler ring and two 64 KiB diagnostic files bound storage; a background thread writes at most every five seconds and on shutdown. Reports contain message/control identifiers, timing and wait-chain type/status/thread IDs, with no input text, coordinates, connection records or object names. Native modal loops can make a dispatch duration span user interaction, so it must be interpreted alongside heartbeat and input age. Application Settings pumps avoid counting nested dispatch time as one slow handler.

Classification order: explicit Bad, fresh supplied indicator, exact Good, optional behavioral/novelty rules. A Rule stores scope and executable hash separately from transient process identity. SHA-256 match keys bound the novelty cache independently of path length. Unknown identity cannot satisfy a hash-bound Good rule.

Notifications are independent of retention: cooldown and snooze suppress delivery, not matching or saved alerts. A maximum of 100 pending notifications is kept in memory; persistent alert history remains available. No-notification operation is not equivalent to clean traffic.

Limitations requiring release work: stricter cryptographic identity for a hostile local administrator is outside scope; short-lived process enrichment is best-effort without process ETW; notification acknowledgements are not durable per UI session; logs cannot prove absence of upstream losses; a privileged attacker can tamper with this app and Windows auditing. See README and PLAN for product coverage and release gates.
